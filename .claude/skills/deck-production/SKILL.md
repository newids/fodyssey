# Deck Production — 발표자료 제작 규칙

## 제출 요건 (`docs/공모전_요강.md` 기준)

- 용도: 발표심사(2026-11-26, 코리아 핀테크 위크) 피칭. 규격 규정은 미확정(요강 §7) — **확정 전 기본값 10쪽 이내**. HTML 덱으로 제작하되 각 슬라이드가 A4/16:9 인쇄에서 1쪽이 되도록 유지한다 (인쇄 → PDF 변환 경로 확보).
- 필수 슬라이드 규정은 없다 — 대신 심사 배점 4항목(산업이해도·기획역량·구체성·독창성, 요강 §5)을 각각 커버하는 슬라이드가 존재해야 한다.

## 서사 구성 원칙

- 슬라이드마다 "심사위원에게 심는 한 문장"을 먼저 정한다. 그 문장을 증명하지 않는 요소는 싣지 않는다.
- 권장 골격(요강 상한에 맞게 조정): 표지 → 문제(정량) → 왜 지금/왜 실패해왔나 → 솔루션 → 킬러 기능 데모 → AI 기술·필연성 → 시스템 구성 → **교육 프로그램 연계·확산 전략(교육생 조직화 포함)** → 타겟·기대효과 → 로드맵·팀 → 클로징.
- 청중에 공무원 의사결정권자가 포함된다고 상정한다 — 정책 정합성·성과 지표·예산 논리가 슬라이드에서 바로 읽혀야 한다 (CLAUDE.md §1-1 ③).
- 기획서의 축약본이 아니다 — 순서와 밀도를 발표 호흡으로 재설계한다. 단 **수치·주장은 기획서와 글자 단위 일치**가 원칙이다.

## 브랜드 토큰

[새 아이디어의 비주얼 방향 확정 후 토큰을 재정의한다] 이전 프로젝트에서 검증된 기본값 (임시 사용 가능):

```css
--paper: oklch(97.5% 0.006 85);  --ink: oklch(24% 0.015 260);
--accent: oklch(48% 0.13 250);   --danger: oklch(52% 0.17 25);
--card: oklch(99.2% 0.003 85);   --rule: oklch(24% 0.015 260 / 0.14);
```
- 폰트: Pretendard 계열 시스템 스택. 에디토리얼 스타일(두꺼운 상단 룰 + 키커 + 스탯 타이포). 첫 덱 제작 시 컴포넌트(stats/cards/chips/timeline)를 정의하고 이후 재사용한다.

## 기술 규칙

- 단일 HTML 파일, 외부 의존성 0. 키보드·휠·터치 내비게이션, 진행 표시, reduced-motion 지원.
- 각 슬라이드: `height: 100dvh; overflow: hidden;` + clamp() 타이포. 스크롤바가 생기면 내용을 쪼개거나 버린다 — 글씨 축소로 해결 금지.
- 수식 표기 금지 (프로젝트 규칙).

## 검증 절차 (제작 완료 전 의무)

1. 로컬 서버로 열어 Playwright(또는 브라우저)로 5개 뷰포트 검사: 1920×1080 / 1280×720 / 768×1024 / 375×667 / 667×375
2. 각 슬라이드 `scrollHeight - clientHeight ≤ 0` 확인 (오버플로 0)
3. 슬라이드 수 ≤ 요강의 쪽수 상한 (표지 포함 여부는 제출 규정 해석에 따르되 초과 금지)
4. 기획서 작업본과 수치 대조 — 불일치 발견 시 기획서 표현을 기준으로 수정
