# 부록 A — 용어와 아키텍처

> 금융 학습 AI 플랫폼: 금융 코디세이 · AI Fintech 텀 프로젝트
> 이 문서는 팀 최종 기획서를 지원하는 참고 자산이다. 기획서 본문이 표로 압축한 용어·기술·구성을 원래 정밀도로 풀어 두었고, 마지막 절에는 금융안전 영역에 한정한 심화 설계를 실었다.

---

## 1. 용어집

| 용어 | 정의 |
|---|---|
| **금융 미션** | 계좌이체·문서 이해·사기 판별 등 실제 금융과업을 수행 형태로 옮긴 학습 단위. 사용자의 수행 결과가 진단의 입력이 된다 |
| **금융역량 진단** | 미션 수행 행동 데이터를 기준과 가중치에 따라 점수화해 현재 역량을 측정하는 기능 |
| **금융역량 프로필** | 미션 수행 결과를 사용자 단위로 모은 역량 기록. 취약 영역에 맞는 학습을 연결하는 기준이 된다 |
| **AI 가이드형 실습** | 미션 수행 중 자연어 안내·피드백을 생성해 붙여 주는 실습 방식 |
| **개인별 학습경로 추천** | 프로필을 근거로 다음에 무엇을 학습할지 순서를 정하는 기능 |
| **기초금융** | 3대 학습 영역의 하나. 계좌이체, 자동이체, 신용점수, 대출금리, 금융문서 이해 |
| **금융안전** | 3대 학습 영역의 하나. 보이스피싱·스미싱·악성앱·기관사칭·투자사기 대응 |
| **생활금융** | 3대 학습 영역의 하나. 지원제도 탐색, 청년·퇴직·연금 정보 이해, 금융조건 비교 |
| **B2B2C** | 은행·증권사·보험사·통신사 등이 플랫폼을 도입해 자사 고객에게 제공하는 수익 구조 |
| **B2B2G** | 금융·소비자 기관, 지방자치단체 등이 도입하는 수익 구조 |
| **Rule-based Scoring** | 사전에 정의한 기준과 가중치로 점수를 계산하는 방식. 학습 데이터 없이도 지금 동작한다 |
| **RAG** | 공식 금융자료를 검색해 답변의 근거로 함께 제시하는 방식. 근거 없는 생성(환각)을 줄인다 |
| **Learning-to-Rank** | 축적된 수행·학습 결과로 추천 순위를 학습하는 방식 |

## 2. AI 3기능 명세

| 핵심 기능 | 적용 기술 | 지금 동작하는 경로(Rule) | 고도화 경로(ML/LLM) | 왜 AI여야 하는가 |
|---|---|---|---|---|
| **금융역량 진단** | Rule-based Scoring → ML(분류/회귀 모델) | 행동 데이터에 사전 정의한 기준·가중치를 적용해 점수화한다 | 축적된 데이터를 학습한 모델로 판정을 정교화한다 | **연령대가 역량의 대리 지표가 되지 못한다는 것이 문제 정의 그 자체다.** 개인별 취약 영역 판정은 축적 데이터를 학습하지 않으면 정교해지지 않는다 |
| **AI 가이드형 실습** | Instruction LLM + Context Prompting + RAG | 미션 단계·사용자 수준을 조건으로 전달해 응답 방식을 조정한다 | 공식 금융자료를 검색해 답변 근거로 붙인다 | 같은 내용을 **사람마다 다른 방식으로 말해야** 한다. 고정 문안 분기는 조합이 폭발하고, 근거를 붙이는 일은 검색과 생성이 함께 필요하다 |
| **개인별 학습경로 추천** | Rule-based 추천 → Learning-to-Rank | 프로필과 사전 정의된 규칙으로 다음 학습을 정한다 | 사용자별 학습효과를 반영해 순위를 학습한다 | **학습효과가 사람마다 다르다**는 전제가 있는 한, 데이터가 쌓이면 순위 학습이 불가피하다 |

**서술 규율.** 세 기능은 전부 「Rule → ML/LLM」의 2단 구조를 갖는다. 기술을 말할 때는 **지금 당장 동작하는 규칙 경로와 데이터가 쌓인 뒤의 고도화 경로를 항상 함께** 밝힌다 — 과장 없이 AI 필연성을 말할 수 있는 형식이다.

## 3. 시스템 구성

```
 사용자
   │  미션 수행 요청
   ▼
 API Gateway  — 인증 / 인가
   │
   ▼
 API server ──── 미션 컨텍스트 ────▶  AI (LLM)
   │   ◀──── 가이드 / 피드백 / 근거 ────┘
   │                                     │  정제 텍스트 임베딩 요청
   │  프로필 조회 · 수행기록 저장          │  임베딩 벡터 근거 검색
   ▼                                     ▼
 Database  ◀────────────────────  Pipeline
                                         ▲
                                         │ 원문 수집
                              금융 공공정보 · 제도 · 혜택정보
```

| 구분 | 흐름 |
|---|---|
| **요청 흐름** | 사용자의 미션 수행 요청이 **API Gateway**의 인증·인가를 거쳐 **API server**로 전달된다 |
| **AI 호출** | API server가 미션 컨텍스트를 **AI(LLM)** 에 전달하고, 가이드·피드백·근거를 받아 사용자에게 제공한다 |
| **데이터** | API server는 **Database**에서 프로필을 조회하고 수행기록을 저장한다. AI는 임베딩 벡터 근거 검색으로 답변 근거를 가져온다 |
| **외부 수집** | **Pipeline**이 금융 공공정보·제도·혜택정보 원문을 수집해 정제 텍스트를 임베딩하고 Database에 적재한다 |

**안전 설계 보충.** 외부에서 수집한 원문은 **AI 1차 검증과 사람 검수를 함께 거친 뒤** 적재해, 검증되지 않은 외부 입력이 답변 근거로 그대로 들어오지 않게 한다.

## 4. 금융위원회 AI 활용 7대 원칙 대응

| 원칙 | 본 서비스의 대응 | 대응 수준 |
|---|---|---|
| **거버넌스** | 금융역량 진단이 **규칙 기반 점수화에서 출발**하므로 기준과 가중치가 문서로 남고 점수 산출이 재현·감사 가능하다. 판정 이력을 기록해 사후 추적이 가능하도록 설계한다 | 설계 반영 |
| **합법성** | 답변 근거는 **공식 금융자료와 공공정보**만 사용하고 개인 금융정보는 수집하지 않는다. 사기 대응 실습은 앱 안의 가상 상황으로 한정한다 | 설계 원칙 수립 (법적 검토는 진행 예정) |
| **보조수단성** | AI는 안내·피드백·추천의 **보조수단**이며 최종 판단과 실행은 사용자에게 있다 | 설계 반영 |
| **신뢰성** | RAG로 **공식 금융자료를 답변 근거와 함께 제시**해 근거 없는 생성을 줄이고, 진단 점수는 규칙 계산 결과로 산출한다 | 설계 반영 |
| **금융안정성** | 실습 환경은 가상이며 **실제 금융 시스템에 대한 쓰기 접근이 없다.** 실습 중 어떤 조작도 실계좌·실거래에 도달하지 않는다 | 설계 반영 |
| **신의성실** | 금융상품을 판매·중개하지 않으며 특정 상품을 추천하지 않는다. 수익은 **API 사용량 기반 과금과 라이선스 구독**에서만 발생한다 | 설계 반영 |
| **보안성** | 프로필은 **가명처리 후 저장**하고 개인 금융정보를 수집하지 않으며, 기관에 제공하는 결과는 **집계 단위로만** 산출한다 | 설계 반영 |

> 7개 전부에 대응이 있으나 대응 수준을 구분 표기한다. 합법성은 법적 검토가 끝나지 않았으므로 "설계 원칙 수립" 단계임을 숨기지 않는다.

## 5. 개인정보 · 안전 설계

1. **최소 수집.** 학습·진단 목적에 필요한 항목만 수집하며, 항목·목적·보유 기간을 고지하고 명시적 동의를 받은 경우에만 저장한다.
2. **가명처리.** 프로필은 저장 시점부터 가명처리한다. 개인 금융정보(계좌·카드·잔액)는 수집 대상이 아니다.
3. **집계 단위 제공.** 기관에 제공하는 결과는 개인 단위가 아니라 집계 단위로 산출하며, **최소 인원에 미달하는 소규모 집단은 산출하지 않는다**(재식별 방지).
4. **가상 격리.** 실습은 앱 안의 가상 상황이며 실제 금융 시스템에 대한 쓰기 접근이 없다.
5. **외부 데이터 검증.** 수집한 외부 원문은 AI 1차 검증과 사람 검수를 함께 거친 뒤 적재한다.

## 6. 금융안전 영역의 심화 설계

**이 절은 3대 학습 영역 중 「금융안전」 영역에 한정한 심화 설계다.** 팀 기획서의 AI 기능 ①「금융역량 진단」은 *사용자의 행동 데이터를 기준과 가중치에 따라 점수화한다*고 밝히고 있는데, 그 점수화를 실제로 계산 가능하게 만들려면 영역별 산식이 필요하다. **아래는 금융안전 영역에 대해 설계한 산식과 실습 절차이며, 기초금융·생활금융 영역의 산식과 세 영역을 하나의 금융역량 프로필로 통합하는 방법은 아직 설계되지 않았다.**

### 6-1. 금융안전 취약도 지수 산식

| 용어 | 정의 |
|---|---|
| **발송(노출)** | 사용자에게 제시된 실습 시나리오 1건. 열람 여부와 무관하게 센다 — 분모 |
| **피격** | 링크 클릭 / 정보 입력·전송 / 사기 시나리오를 "정상"으로 판정 — 분자. 규칙 계산으로 판정한다 |

```
개인 지수   V(u,L) = ( Σ wᵢ · hitᵢ ) ÷ ( Σ wᵢ ) × 100      (0~100, 낮을수록 안전)
가중치      wᵢ = 0.5 ^ ((r_now − rᵢ) / H)                    H = 반감기, 기본 3회차
산출 조건   자극 유형 L의 누적 발송 n ≥ 3 일 때만 산출. 미만은 "측정 중"
집단 집계   기관·지역 단위 집단 소속 사용자 지수의 평균, 1회차 대비 개선폭을 함께 제공
최소 인원   집단 인원이 기준(기본 30명)에 미달하면 산출하지 않는다 — 재식별 방지
```

- **최근 회차에 가중하는 이유.** 반년 전 결과와 지난주 결과를 같은 무게로 더하면 "지금 이 사람이 얼마나 위험한가"에 답하지 못한다.
- **자극 유형 라벨은 콘텐츠 제작 시점에 사람이 검수해 고정한 메타데이터**이며, 지수의 분자·분모에는 사람이 검수한 라벨과 규칙 판정 결과만 들어간다.
- 반감기 3회차와 최소 인원 30명은 **근거 있는 상수가 아니라 운영 기본값**이다. 도입 기관의 규모·정책에 따라 조정하며 최소 인원은 상향만 한다.

### 6-2. 실습 절차와 유형

| 구분 | 내용 |
|---|---|
| **5단계 절차** | 사전 행동수칙 안내(3분) → 취약 유형 진단 → 무예고 시나리오 → 사후 분석 → 재평가 |
| **설계 제약** | 1회 3분 이내 · 앱 안의 가상 수신함(실제 발송 없음) · 실계좌·실개인정보와 분리 |
| **실습 유형** | 판별형(기관사칭 소재 40% 이상) · 행동형(행동수칙·모의 이체, 진입 시 1회) · 생활과제형(생활 과업 수행 중 사기 소재를 함께 다룸) |

- 시작을 행동수칙 안내로 두는 이유는 **수칙을 모르는 상태의 실패는 학습이 아니라 좌절**이기 때문이다. 예고 없이 도착하는 것은 개별 시나리오의 시점이지 실습 참여 사실이나 행동수칙이 아니다.

### 6-3. 미설계 항목 (정직 표기)

- **기초금융·생활금융 영역의 진단 산식은 설계되지 않았다.**
- **세 영역의 결과를 하나의 금융역량 프로필로 합산하는 방법도 설계되지 않았다.**
- 이 지수는 **외부 훈련 지표(예: 기업 대상 모의훈련의 열람률·클릭률)와 직접 비교하지 않는다** — 측정 대상과 참여 조건이 다르다.

## 7. 향후 발전 방향 — 3단계

| 구분 | 타겟 사용자 | 목표 | 실행 전략 |
|---|---|---|---|
| **1단계** | 시니어층 | 실제 행동 변화 입증 / PoC 성공 및 레퍼런스 확보 | AI 기반 대화형 인터페이스 도입 / 밀착형 시나리오 미션 구성 |
| **2단계** | 청년층, 중장년층 | 사기 유형별 시나리오 다각화 / 플랫폼 체류 시간 증대 | 게이미피케이션 콘텐츠 도입 / 금융 서비스의 실질 혜택 연계 |
| **3단계** | 청소년층, 전 연령층 | 공공 교육 인프라 편입 / 사용자 데이터 기반 DaaS 구축 | 청소년층 특화 시나리오 개발 / 연령별 데이터 수집 및 가공 |
