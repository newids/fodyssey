# Proposal Writing — 기획서 작성 규칙

## 형식의 주인은 요강 문서다

`docs/공모전_요강.md`가 요구하는 것 외의 형식 실험은 감점 요인이다. 최종 제출본 요건:
- 제출 서류: 참가신청서 + 동의서 + 아이디어 기획서 (요강 §4)
- 기획서 분량 상한·양식: **미확정** (요강 §7 — 핀테크포털 공고문 확보 시 확정). 확정 전에는 A4 2~3쪽 밀도로 작성하고 렌더링 실측을 기록해, 양식 확정 시 저비용으로 재조판 가능하게 유지한다.
- 필수 항목 규정은 없다(자율 주제) — 대신 심사 배점 4항목(요강 §5)이 사실상의 필수 구성이다.

## 지면 배분

[기획서 양식 확보 후 항목별 배분표를 재작성한다] 배분 원칙 (이전 공모전에서 검증됨):
- **심사 배점 정렬**: 산업이해도·기획역량·구체성·독창성(각 25점) 각각에 대응하는 지면을 명시하고, 채점자가 항목별 근거를 30초 안에 찾을 수 있게 배치한다. 타당성(75점) 쪽에 지면을 몰아준다.
- 심사의 첫 판단 지점(문제 정의)과 차별화·기술 필연성에 지면을 몰아준다.
- 각 항목의 배분을 쪽 단위 수치로 명시하고, 분량은 추정이 아니라 렌더링 실측으로 확인한다.
- 넘치면 줄이지 말고 버려라 — 압축된 문장 12개보다 완전한 문장 8개가 읽힌다.

## 작성 규칙

- **정량 근거 병기**: 모든 통계는 기준 연도·출처를 붙인다 (예: "기관명, 기준 연도·분기"). 출처는 팩트체크 완료된 프로젝트 브리프(`PROJECT_BRIEF.md`, 신규 작성본)의 수치만 사용한다.
- **수식 표기 금지**: LaTeX/MathJax 금지 (프로젝트 규칙 — 모바일 가독성).
- **AI 기술 적용은 표로**: 기능 | 적용 기술 | 선택 이유 3열. "LLM 사용"이 아니라 "왜 규칙 기반으로는 안 되는가"가 드러나야 한다.
- **근거 없는 주장 금지**: 전략 문서에 근거가 없으면 `[TODO: 근거]`로 표기한다. 그럴듯한 수치 창작은 즉시 반려 사유다. 전략의 현실성 점검표에 등재되지 않은 전략 요소는 기획서에 쓸 수 없다 (CLAUDE.md §1-1 현실성 게이트).
- **공무원 독자를 상정한 서술**: 공공·정부 지원 연계형 모델이므로, 담당 공무원이 상부·대외에 그대로 보고할 수 있는 언어로 쓴다 — 정책 정합성(관련 정책·사업명 명시), 성과 지표(측정 가능한 KPI), 예산 논리(소요 재원과 근거)를 갖춘 문장을 우선한다.
- **연계·확산은 독립 서술**: 기존 교육 프로그램과의 연계 방안과 구현 후 확산·영업 전략, 교육생 조직화 프로그램은 부록이 아니라 본문 요소로 다룬다 (요강 항목 구조에 맞춰 배치).

## 시스템 구성 (아키텍처) 표현 수준

- **설계 수준 다이어그램만** 작성한다: 컴포넌트 박스 + 데이터 흐름 화살표 (텍스트 다이어그램 또는 mermaid). 데이터 아키텍처(수집→저장→학습→서빙 흐름)를 포함하면 강해진다.
- MVP 코드 구현은 기획서 작성 범위 외다(mvp-builder 담당) — 아키텍처를 근거로 구현에 착수하지 않는다.
- 다이어그램의 각 컴포넌트는 "AI 기술 적용" 표의 행과 대응돼야 한다. 표에 없는 박스, 박스에 없는 기술이 있으면 정합성 결함이다.

## 개정 시 규칙

- 전면 재작성 금지 — 전략이 바꾼 부분만 수술적으로 고친다.
- 버전 규칙: 정본은 `docs/idea/기획안_v{N}.md`, 작업본은 `_workspace/03_proposal_draft.md`.
- 개정 후 자가 점검: ① 요강의 필수 항목 모두 존재? ② 분량 상한 이내(렌더링 실측)? ③ 모든 수치에 출처? ④ 다이어그램-기술표 대응? — 하나라도 실패면 제출 불가 상태로 보고한다.
